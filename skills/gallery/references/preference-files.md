# Writing preferences

Before writing or revising a document, take the enabled files from the `写作偏好：` lines of `gallery list` or `gallery new`, or from `gallery preferences list`: enabled files only, in configured order, with titles and absolute paths. Select the applicable files by title and scope, then read their contents; don't apply every report type to every task. For conflicts: the current user request, then applicable preferences in listed order (earlier first), then the skill.

A new Gallery starts with only `<home>/preferences/通用写作.md`, Gallery's short generic default. An older workspace's `<home>/preferences.md` is migrated to `<home>/preferences/项目报告写作.md`, preserving its body, enabled state and order. Every preference lives in `<home>/preferences/<name>.md`. Settings → 写作偏好 creates/duplicates/renames/deletes tabs, reorders them and switches each on or off. A tab rename updates the Markdown filename and title; the initial document follows the same rules as all other preferences. Renaming or deleting it never recreates an extra default. Saving saves all modified tabs; switching tabs keeps their unsaved work. Closing with unsaved changes (a click outside, ×, Esc) asks first: 继续编辑, 不保存, 保存并关闭. The Gallery package holds two example preferences for a project report, Chinese and English, in its `assets/preference-examples/`; 写作偏好 offers them once, in a note at the top of the dialog.

Enabled state and order are in `gallery.json` under `preferences: { order: [...], off: [...] }`, with paths relative to home. Unlisted new files are enabled at the end; missing files are ignored. Disabled files stay in place and are not instructions for the current task. `gallery preferences list --all --json` includes disabled files for managing settings; `gallery preferences on|off <name>` changes one. Only change files, order or enabled state when the user asks. Never add preferences on your own. Custom pages do not use document writing preferences.
