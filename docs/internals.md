# Maintainer notes

These notes are for developing Gallery itself. People writing documents (and Agents using the skill) do not need them: their entry point is `SKILL.md`, which has them run `gallery preferences list` and read the applicable enabled writing preferences (写作偏好, `<home>/preferences/*.md`; a new workspace starts with `通用写作.md`, Gallery's short generic default) and `skills/gallery/references/writing-html.md`, the whole of what the skill holds for them ("Packaging" below). This file is the overview. Each system has its own document: [render.md](render.md) (the shared kit, checks, build and export), [editor.md](editor.md) (editing on the preview page and saving), [workbench.md](workbench.md) (the workbench, its session with a document page and its commands) and [testing.md](testing.md).

The user's documents live in a workspace (`src/shared/workspace.mjs`), a folder found in this order: `--workspace <dir>` (the gallery command sets `GALLERY_WORKSPACE` from it before anything is loaded), `GALLERY_WORKSPACE`, the nearest folder up from the current one holding a `gallery.json` that says `{ "gallery": "workspace", "version": 1 }` (another program's `gallery.json` is not one), else `Gallery` in the user's Documents folder, `~/Documents/Gallery` (`documentsFolder()`: on Windows the one Explorer shows as 文档, the registry's Personal shell folder (read once a process: a server asked for it some 300 times a page, each reg.exe some 30 ms) with its variables expanded, OneDrive's when OneDrive backs it up, read only when the home is the user's own, so a test or a sandbox naming another `HOME`/`USERPROFILE` gets that home's `Documents`; on Linux the XDG documents folder of `user-dirs.dirs`, `~/文档` on a Chinese desktop; a folder that is not there is passed over; on macOS `~/Documents`). `defaultWorkspace()` is that folder, or the one `GALLERY_DEFAULT_WORKSPACE` names (the browser scenarios' studio): the workspace the sidebar's 默认文档 column and the drafts that join its tree (`joinDefaultTree`) are about, which is not always the one `findWorkspace` returns. `npm run dev` uses home too; tests set both GALLERY_DEFAULT_WORKSPACE and GALLERY_DATA_DIR to isolated folders. Its root shows the user's things only; everything else Gallery keeps is under `.gallery/`:

A document is a folder at the root holding `doc.html` or `report.html` whose name is a slug: never `exports`, a dot name or a name Windows keeps for a device (`con`, `nul`, `com1`…: a workspace moves between systems), and never an old layout's 写作偏好 page (`"instructions": true`). A folder holding neither (a user's own `materials/`) is left alone. A slug a page holds in `.gallery/pages/` is taken, and so is a custom page's (`pages/<slug>/`): documents and custom pages share one set of slugs (`slugTaken`; `src/shared/pages.mjs` `pageSlugRefused` the other way). `pages/` is as `components/` below: a name no new document takes, hiding nothing (a document called `pages` made before them stays one, its own files and `assets/` and `materials/` beside the pages' folders, no page being called either; trashed, copied or restored it takes what is its own alone), passed over by what walks the documents. `components/` holds custom blocks and no document, so it is passed over by what walks the workspace's documents (the list, search, `gallery check`, an export, an import, the watcher's report of documents), and it is no slug a new document takes (`keptName`: `gallery new`, the workbench's next free name, an import), but it hides nothing: a document called `components`, made before the custom blocks came, stays one, its folder shared with them. A copy of it or the trash takes what is its own, its files and `assets/` and `materials/`, and leaves all else, a custom block being written too; back from the trash it stands where it stood, as its address goes by its folder name, unless something took a place of its there, when it takes the next free name. Old data is never rewritten: an old reports/ folder is copied in by `copyOldDocuments` (`gallery init --from`), which only reads it, takes a custom block along when the workspace does not hold it and leaves a document called `components` behind, on a line of its own. `adoptOldLayout` copies a workspace's own old layout (`.workspace.json`, `.trash/`, `.emoji-library/` and the edit state in `node_modules/.cache/report-edit`) into `.gallery/` once (`.gallery/migrated.json` says it was done), the old copies left; nothing calls it now but its test, `tests/unit/workspace-layout.mjs` (the dev server's `adoptWorkspace` no longer does).

The machine keeps a registry of the workspaces used on it (`src/shared/workspace-registry.mjs`, since 2026-11-08), outside every workspace: `workspaces.json` in the user's data folder (`userDirectory("data")` of `src/shared/user-directory.mjs`: `%LOCALAPPDATA%\gallery` on Windows, `~/Library/Application Support/gallery` on macOS, `$XDG_STATE_HOME/gallery` or `~/.local/state/gallery` elsewhere; `GALLERY_DATA_DIR` first, which `tests/unit/workspace-env.mjs`, the browser harness and the release smoke test set to folders of their own), `{ version: 1, workspaces: [{ root, seen }] }`. The gallery command registers the workspace it found (every command but `stop` and `skill`; `init` and `workspaces --name` once they made it), and so does a server as it starts listening (`routes.mjs` `listening`), `seen` written again an hour later at the soonest; including explicitly used temporary workspaces; a folder whose `gallery.json` is not Gallery's is not registered. A change is made under the registry's lock (`workspaces.json.lock`) on the file as it is then and renamed over it, so that commands registering at once keep each other's; a data folder that cannot be written (Windows' rights, an Agent's sandbox: `EPERM` three times with no lock there) is given up at once, so that no command waits for the lock. Each workspace has a short id, `ws-` and six hex digits of the hash of its path (lower case on Windows): `workspaceId`. A workspace is called by its `gallery.json`'s `name`, else by its folder's name, climbing past `gallery`, `docs`, `outputs`, `reports` and `文档` but never to the home, the Documents folder or a drive's root (a workspace that is one called by the drive, `E:`); two of the same name are told apart by the folder above, and where that is alike too by their own paths (`src/shared/workspace-name.mjs`). The name is written into `gallery.json` as `pages.homeMade` is, the file's own layout kept (`objectAt` and `ownLine` of `src/shared/pages.mjs`). `gallery workspaces` and `gallery list --all` read it (render.md).

Each system imports only itself and `src/shared/`; only `src/server/` (which wires them into `dev:local`), `src/cli/` and `src/transfer/` (which runs the editor's modules and the render's offline file on the server) import several. What one system needs of another is handed to it: the workbench's service gets the render system's "new document from the starter" and "export" from the server, and the editor's save queue and checks. Code that runs in the browser (`render/kit/`, `editor/page/`, `editor/components/` but for the server's file.mjs modules, `workbench/app/`) imports nothing that needs Node; the editor's is served as it is, so it imports by relative path only. `tests/unit/boundaries.mjs` holds all of this, so a stray import fails `kit:check`.

## Components

### Four kinds of block

Every component is one of four kinds, by what the reader does with it in the live preview (its description's `category`, `CATEGORIES` in `src/shared/components/index.mjs`; the editor takes each unit kind's from its component, `UNIT_CATEGORY` in `components/registry.mjs`):

| Kind | What the reader does with it | Components | Still to change (`pending`) |
| --- | --- | --- | --- |
| 基础块 (`block`) | edits its text, makes it and turns it into another type on the page, splits and merges, moves, deletes, copies | paragraph and small text, headings 1–4, lists (bulleted, numbered, to-do, flowchart) and their items, quote, code block, divider, formula block | — |
| 容器块 (`container`) | holds basic blocks, edited as anywhere; moves and deletes it as a whole | section, highlight panel (the opening summary), callout, disclosure, detail card, Sheet area and its tabs, table, a row of columns (分栏: `columns`, made by dropping a block beside another or by 分栏 in a block's menu) | — |
| 卡片块 (`card`) | moves and resizes it as a whole, edits its title and caption; its inside is the document's or the kit's | figure (卡片块; the reader's 图形, Figure, since 2026-11-20): a figure, a chart of a type the document defines or a drawing of the document's own in HTML, CSS or SVG (a diagram, a timeline), or an image (`chart`: `within: "card"`) | — |
| 整体块 (`whole`; Layout in English, the name a block of it goes by when it has none of its own) | moves it as a whole | a document's own element (a class of its own) that is no figure, a layout such as a strip of metrics or a comparison panel, a diff (`.doc-diff`), controls of reading state (`.doc-state-fields`, `.doc-filter-row`, `.doc-state-list`), an instance of a custom block (`installed`, editor.md "Instances of custom blocks"; its slots, `data-doc-slot`, hold the document's blocks, boxes of kind `slot`) | a document's own element's text is still edited in place; it is to be moved alone |

A to-do list and a flowchart (流程图) are lists: classes of the list's description (`list.mjs`: `doc-todo`, `doc-flow` with the author's `data-direction` (on the list and on a step) and `--doc-flow-ratio` (a step's weight in its row), and the kit's `data-doc-flow-key` (what its stylesheet of rows names it by) and, for a moment as items move, `data-doc-flow-recount`), types of the list's editor component (`components/list/`: `todo`; `components/flowchart/`, which edits the list description's flowcharts: `flowchart`), each with a style file of its own (`todo.css`, `flowchart.css`) and a flowchart's rows and arrows a part of the kit's runtime (`runtime/flowchart.js`, which imports the description's names, its layout's measures `FLOW_ROW` and its rule of a row's shares `flowShares()`, and writes them into a stylesheet the document adopts, never on the steps; the page editor's gaps, `page/columns/`, go by the same measures and rule). A step is a node, a container as a highlight block is (its icon first, its title a paragraph, then its content): for the editor a unit of kind `step` (an li whose parent is an ol.doc-flow, a match rule by its parent) and a box of kind `node` (`components/flowchart/`), which the server finds a step written so to be (`source/units.mjs` `flowNode`), in a flowchart's box of kind `flowchart` that takes steps alone.

A card is copied as itself (and so are a table and a row of columns: `copy: "itself"`, `COPIED_AS_ITSELF`); a formula block is copied as its TeX. The page itself, inline marks (`text`) and reading state bound to blocks of any kind (`state`) are of no kind.

`tests/unit/components.mjs` holds the descriptions together: every `data-*` attribute and `doc-*` name in the kit's sources is described (written by authors, set or generated by the kit, used inside what it generates, or an event), no name is both an author's and the kit's, the Skill's documents, the markup reference of docs/ (the cards, quick-reference.md, visual-design.md, report-contract.md) and the editor tell authors to write only authors' names (a custom page's own attributes on its boards and cards, `data-card-id` and the rest, `page-cards.mjs` `PAGE_ATTRIBUTES`, being the page's: no document's component describes them; and a name the kit sets that an author's own style selects on, `:root[data-doc-effective-theme="dark"]`, being read, not written), the selectors find the same elements in a parsed source as in the browser, and every editor component edits the description of its name and is of its kind. A new component gets a description there, its files in the assets' list if it has any, its kit code (registered with the kit's runtime, [render.md](render.md) "Runtime") and style, its editor folder, its card (`docs/components/`), and an example in the Component Catalog; the tests name what is missing. Every instance starts from its markup: a document's script defines types of its own, never wires an instance.

## Reading a document

`gallery read <document>` (`src/cli/read.mjs`, 2026-11-14) prints a document for reading and writes nothing: no file, no block id, no export, no workspace made or registered (`MAKES_NOTHING` in `src/cli/gallery.mjs`), with no server needed; it reads `doc.html` as the file is now. Its view (`src/transfer/read-view.mjs`) opens the page as the page editor opens it, in the command's own process (`src/transfer/dom.mjs` `openReportPlaced`: natural HTML made the kit's in memory by `shownSource`, which adds no line, every unit and box marked, and where the parser found each node, the page's `data-ge-*` marks taken off its offsets), then makes a tree of the page's nodes (`nodesOf`): units by their kind, wrappers (what holds units and is none: the header, a detail card of the file, a plain group, an element of the page's own) and loose pieces (words straight in a flow, an element the editor makes no block of); a box another block owns (a Sheet panel, `boxOwner`) puts its blocks under that block. The view knows no kind: each kind of unit says how it is read in its definition (`read`: its name, the rows of the default view written with `src/editor/components/read-rows.mjs`, its words, its JSON's data, what the export's Markdown leaves out of it, its Markdown alone; `components/registry.mjs` `READS`), and `tests/unit/read.mjs` fails on a kind with none and on a row of "Blocks at a glance" with no mark of it in the example report's view. The default view (`--format full`) is a row per line, its left column the line in `doc.html` and the `data-block-id` of the block starting there; Markdown where Markdown says it, `┌─ <name> … └─` around a block that holds blocks or that Markdown cannot say, a `── <name>` row opening a list, a quote, a table or a code block, and `{…}` after a block holding its classes and attributes as the file has them (the classes that make it its kind left out: the definitions' and the kit's descriptions'); it ends saying all its blocks are there, or with a 提示 line naming each unit no row wrote (`unwritten`, which the tree is checked against) and each script, style or template a flow holds. The other formats: `markdown` the export's (`markdown.mjs` `reportMarkdown`; a part by `markdownWriter`), its page blocks titled as they show and a comment at its end saying what it left out; `text` each block's words; `html` the file's own text of `<main>` or of the part, exactly (whole lines while the file still holds natural HTML, whose lines are the page's but whose offsets are not); `json` every node with its kind, place, line, words, Markdown, HTML, attributes and data. A part is one block (`--block`, or an address naming one), a heading's section as the page folds it (`--section`, by id or by the heading's words), the outline (the headings the page's 目录 lists) or the map (every node a line). When the server announces itself and the reader's page of the file has edits not saved or a conflict (`/__gallery/workspace/status`, as `gallery status` asks), a 提示 line says so.

## Who owns which state

Three kinds of state, each with one owner; a new feature puts its state in one of them and never keeps the same setting in two places.

| State | Examples | Owner | Changes the source? |
| --- | --- | --- | --- |
| Document content | text, chart data, a card's width or color the author (or the reader, in the editor) set; its look (字体与布局) | `doc.html` / `doc.json` (`report.html` / `report.json` in a document made before Gallery 0.1) | only through a commit (the editor's autosave); the look, `doc.json` alone, through the workbench's `POST look` |
| Reading state | the Sheet shown, sort order, open disclosures, theme and width mode, a memo field | `DocState` and the display settings (`localStorage`), carried by "导出当前视图副本" | never; making it the default is an explicit edit of the source |
| Agent's changes under review | the baseline, the counts | the edit service (`.gallery/state/changes/`) | never; 撤回 writes the baseline back as a write of the reader's |
| Editing session | caret, selection, undo history, what waits to be saved (the crash buffer), conflicts, the format brush and recent colors, the outline's and the headings' folds | the editor (page memory; the crash buffer, the journal of what the page committed and made (`gallery-edit:<slug>:journal`, `page/autosave.mjs`, beside the crash buffer and the lost list: [editor.md](editor.md) "Someone else's writes") and the folds in `localStorage`, per document, the tab's id and its committed texts in `sessionStorage`) | never; only a commit turns it into document content |

The editor never writes reading state into the source and the kit never persists document content in storage.


What runs where: `src/shared/paths.mjs` knows the release by its `release.json` and names the package's folders instead of the checkout's. The bundle stands in for what only a source checkout runs (esbuild: the kit's build and the components' runtime, `kit-build.mjs`'s `loadKitFile` reading `kit/` instead; Vite; shiki), each a function that throws "not in the release" when called, and the build fails when the metafile says any of them, TypeScript, pdf.js or `@napi-rs/canvas` was bundled. TypeScript is required by its file, only when a command checks a script (`src/render/typescript.mjs`); pdf.js is imported by its file, only for a PDF's import (`src/transfer/import.mjs`). jsdom is bundled, its two reads of its own files made in the bundle (its default stylesheet's text put in; the synchronous XMLHttpRequest's worker, never used, named only), and css-tree's JSON taken in. The editor's browser modules are not bundled: the server imports them from `browser/`, the files it serves the page, as the checkout's server imports them from `src/` (several make the page's own scripts of their functions' text, which a bundle's renamed or minified names would break); the two that reach a package (`shared/new-names.mjs`: parse5) are bundled. A gallery command starts the release's server as `node <package>/dist/server.mjs --port <n>` (`src/cli/server-process.mjs`), detached, in the user's home folder (never the caller's folder, which Windows would keep from being deleted, nor the package's); `gallery serve` runs it in its own process. The stamps of the editor's modules and the kit's files are their contents' hashes, from `release.json` (npm gives every file of a package one time, so a stamp of times would outlive an upgrade). The server watches `release.json` and stops when it changes or goes (`npm i -g` of another version): its chunks, modules and kit are then another version's; the next command starts the new one. On Windows its recursive watch of the workspace holds the workspace folder: it cannot be renamed while a server runs.

Measured on 2026-10-28 (Windows 11, Node 24): the tarball 7.8 MB, 25.2 MB unpacked, 745 files, installed with no dependency. The biggest parts: `dist/` 7.3 MB (jsdom and what it needs, about 5 MB of it; puppeteer-core, about 1 MB), `vendor/typescript/` 5.7 MB (the type check of a document's scripts), `browser/` 4.6 MB (the editor's modules 2.4 MB, the emoji and icon data 2.2 MB), `vendor/pdfjs/` 3.6 MB (CMaps 1.4 MB, the worker 1.3 MB), `kit/` 1.5 MB (`code.js`, shiki, 1.2 MB), `vendor/types/` 0.9 MB, `vendor/` d3 and KaTeX 0.8 MB, `web/` 0.4 MB.

`npm run test:release` (`tests/release/smoke.mjs`, [testing.md](testing.md)) builds it, packs it and installs the tarball into a prefix of its own, then runs it there.

## Single service (0.2.2)

Service discovery uses `userDirectory("data")/server.json`, with `port,pid,token,nonce,kind,version,started,home`; a data-directory lease prevents a second server. The one token is `<data>/token`, logs `<data>/logs/server.log`, and sticky port `<data>/last-port`. The default workspace owns configuration, preferences, components, extensions, pages and the shared outline. Other registered folders contain document files and their own state/trash/QA/export data. CLI workspace discovery selects document storage; page/block/extension commands always select home. Foreign init creates only gallery.json. Development uses the same profile model; tests isolate both data and home.

Foreign documents use `/~<ws-id>/generated/<slug>.html` and the same prefix on media/edit APIs. The browser’s address is `#~<ws-id>/<link>`. Roots come only from the registry. Each runtime keeps independent document queues and indexes, with the shared token and global catalog. No legacy server announcements or foreign configuration are read, and no migration runs.
